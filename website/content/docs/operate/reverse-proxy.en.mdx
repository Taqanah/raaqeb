title: Reverse proxy and TLS
description: What the proxy in front of Raaqeb must pass and allow, with tested snippets for Caddy, Nginx and Traefik, and when to turn on HSTS.
---

Raaqeb serves plain HTTP and leaves TLS to a reverse proxy. The proxy must pass the host the visitor asked for, and add `X-Forwarded-For` and `X-Forwarded-Proto`. Raaqeb believes those headers only from its trusted proxies, set on the general settings page or by `RAAQEB_TRUSTED_PROXIES`. A proxy on the same server connects from `127.0.0.1` or `::1`. Once the proxy is in place, open the setup check page under settings through it: it names the address the request came from when that address sent forwarded headers without being trusted, and says whether the public address is the address the browser is at.

The trusted proxies decide the client address that the [rate rules](#rate-rules), the sign-in log lines and a heartbeat's source address read. Without them, behind a proxy, every visitor is the proxy, so every visitor shares one count of each rule.

Three requests need more of the proxy than a page does:

- an import uploads the export file, up to 4 GB, so the proxy must not cap a request body below the file's size;
- "test now" on a monitor and "send test" on an email channel hold their request up to 70 seconds while nothing is sent;
- downloads stream as they are made.

Each snippet below was run in front of a stand-in for Raaqeb: it passes the host and the forwarded headers, a 200 MB upload streams through, a 100-second upload passes whole, and an answer that takes 90 seconds arrives. Each one reaches Raaqeb at `127.0.0.1:3000`, so set the trusted proxies to `127.0.0.1`. Write `127.0.0.1`, not `localhost`, which may resolve to `::1`.

## Caddy

Caddy gets and renews the certificate itself, passes the host and the forwarded headers, replacing any the client sent, and limits neither a body's size nor a request's time:

```text title="Caddyfile"
raaqeb.example.com {
	reverse_proxy 127.0.0.1:3000
}
```

[Custom domains](/en/docs/operate/custom-domains) adds them to it. Under Docker Compose, `deploy/Caddyfile` is this with Raaqeb's container name.

## Nginx

```nginx
server {
	listen 443 ssl;
	server_name raaqeb.example.com;
	# ssl_certificate and ssl_certificate_key, from certbot or your own
	client_max_body_size 4g;
	location / {
		proxy_pass http://127.0.0.1:3000;
		proxy_http_version 1.1;
		proxy_set_header Host $host;
		proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
		proxy_set_header X-Forwarded-Proto $scheme;
		proxy_set_header X-Forwarded-Host $host;
		proxy_request_buffering off;
		proxy_read_timeout 300s;
	}
}
```

- `client_max_body_size` is 1 MB by default, which refuses an import.
- `X-Forwarded-Host` must be set here: Nginx otherwise passes on whatever the client sent, and Raaqeb believes it from a trusted proxy.
- `proxy_request_buffering off` streams an upload to Raaqeb; without it Nginx writes the whole file to its own disk first.
- `proxy_read_timeout` is 60 seconds by default, which cuts "test now" short.

## Traefik

Traefik passes the host and the forwarded headers, replacing any the client sent. Its entry point reads a whole request within 60 seconds by default, body included, which cuts a slow import's upload; set `readTimeout` in the static configuration. A finite value there caps how long an upload may take.

```yaml
# Static configuration
entryPoints:
  websecure:
    address: ":443"
    transport:
      respondingTimeouts:
        readTimeout: 0
certificatesResolvers:
  letsencrypt:
    acme:
      email: you@example.com
      storage: /etc/traefik/acme.json
      tlsChallenge: {}
providers:
  file:
    filename: /etc/traefik/dynamic.yml
```

```yaml
# /etc/traefik/dynamic.yml
http:
  routers:
    raaqeb:
      rule: Host(`raaqeb.example.com`)
      entryPoints: [websecure]
      service: raaqeb
      tls:
        certResolver: letsencrypt
  services:
    raaqeb:
      loadBalancer:
        servers:
          - url: http://127.0.0.1:3000
```

Traefik reaches `127.0.0.1:3000` when it runs on the host. In a Docker network, the URL names Raaqeb's container and the trusted proxies name Traefik's address.

## HSTS

Once the public address on the general settings page starts with `https://`, Raaqeb sends `Strict-Transport-Security: max-age=31536000` on its pages: a browser that opened one over https goes straight to https at that host for a year. It adds nothing more, no `includeSubDomains` and no `preload`, and the API, the images, the feeds and the badges go without it.

To cover every answer, set the header at the proxy. Before you do:

- Turn it on once https works at every address the proxy serves for Raaqeb, [custom domains](/en/docs/operate/custom-domains) included. A browser that holds the header refuses plain http at that host until `max-age` runs out, and nothing the server sends later takes that back.
- Start with a short `max-age`, such as `300` (five minutes), and raise it to `31536000` (a year) once nothing breaks.
- `includeSubDomains` holds every subdomain of the host to https too, a site on plain http among them. Add it only when every subdomain serves https.
- `preload` asks the browsers to build the host into their own list, and leaving that list takes months. Use it only for a domain whose every subdomain is yours and serves https, with `includeSubDomains` and a `max-age` of a year or more.

Each snippet below replaces Raaqeb's own header rather than sending a second one, and was run in front of a stand-in that sends Raaqeb's header. Raise `max-age` when you are ready.

```text title="Caddyfile"
raaqeb.example.com {
	header {
		Strict-Transport-Security "max-age=300"
		defer
	}
	reverse_proxy 127.0.0.1:3000
}
```

`defer` sets the header after Raaqeb answers, so it replaces Raaqeb's.

```nginx
# Inside the location block above
proxy_hide_header Strict-Transport-Security;
add_header Strict-Transport-Security "max-age=300" always;
```

`add_header` alone would send Nginx's header beside Raaqeb's, and `always` sends it on an error answer too.

```yaml
# /etc/traefik/dynamic.yml, beside the router above
http:
  middlewares:
    hsts:
      headers:
        stsSeconds: 300
  routers:
    raaqeb:
      middlewares: [hsts]
```

Traefik sends the header on an https request only, which every request through the `websecure` entry point is.

## Rate rules [#rate-rules]

From 0.3.0, Raaqeb counts each request sent with a body, and each request under `/api/auth/`, by its client and its kind, before it reads the request. The client is the address behind your trusted proxies. An IPv6 address counts by its /64, and its /48 together has four times a /64's allowance.

| Request | At once | Then one more every | Counted by |
|---|---|---|---|
| Signing in, the second step, setting a new password, accepting an invitation | 6 | 10 seconds | client, then a known browser's own |
| Asking for a password reset email | 3 | 60 seconds | client |
| Subscribing to a status page | 5 | 2 minutes | client |
| A private page's password | 10 | 6 seconds | client |
| A heartbeat call that carries a body | 30 | 2 seconds | its monitor's token |
| Anything else, starting a sign-in through single sign-on included | 20 | 1 second | client |

- **Past its rule,** a request is answered `429` with `Retry-After`, the seconds until it may be sent again. The sign-in form says "Too many attempts. Wait a moment and try again." The subscribe form says "Too many sign-ups from here. Try again in a few minutes."
- **A signed-in operator's saves** are never counted. Signing in, reset emails, subscribing and a private page's password count for them as for anyone.
- **A body must arrive whole within two seconds,** or the request is answered `408` and its connection closed. When the requests of one kind already hold every place Raaqeb keeps for them (16), the oldest body still arriving gives its place to the newest request and gets the `408` at once. A real form's body arrives with its request, so only a body sent byte by byte waits.
- **A browser's post from another site** is answered `403` and counts against nothing, so a page someone opens cannot spend their network's sign-ins. A heartbeat call is the exception, since a job may call from anywhere.
- **A heartbeat call carrying a body** is let in by its token, before its body is read. A token no monitor has is answered `404` at once, and a job's first call after a restart also counts against its client's "anything else" allowance. A flood from elsewhere cannot spend a monitor's own allowance.
- **The counts are kept in memory** for at most 10,000 clients, so a restart clears them. Past that many, new clients share one count for each rule.

### Known browsers and password tries [#known-browsers]

- **A known browser:** a browser where someone signed in to an account (with a password and the second step, through single sign-on, or by accepting an invitation), or opened a valid password reset link, is known for that account for 400 days, renewed at each sign-in. The account's known browsers share one allowance besides their networks', for when others on a network have spent it, and are let in even when every place for sign-in is taken. Signing in again does not add to it.
- **Losing it:** ten wrong passwords for the account from its known browsers in a quarter of an hour, and they count as anyone else's again.
- **Other browsers:** an account takes ten password tries in a quarter of an hour, and the install checks at most five passwords a second, from browsers not known for it. Past either, the try is refused before the password is checked, with the same "too many attempts" sentence, whether or not the address has an account.
- **Your way in during a flood:** ask for a password reset email, or run [`raaqeb reset-password`](/en/docs/operate/commands) on the server, and open the link. The browser that opens it is known from then on: setting the new password and signing in spend the account's known-browser allowance, which strangers cannot spend, so a flood of others does not refuse them.

### Behind a proxy that is not trusted [#untrusted-proxy]

Every request comes from the proxy, so each rule is one count for everyone together:

- **A signed-in operator's saves** are never refused.
- **A visitor** meets "too many" once a few others have used the same form: six sign-ins, then one every ten seconds, for the whole world; five subscriptions, then one every two minutes.
- **An operator signing in from a known browser** signs in.
- **On any other browser,** they share those six sign-ins with every stranger, so anyone who keeps sending sign-ins keeps them out; the reset link above is their way in.
- **Heartbeat calls** keep their own count, by token.

The setup check page says so when it sees forwarded headers from an address that is not trusted. Set the trusted proxies, and each visitor counts alone.

**Before 0.3.0,** sign-in allowed three attempts in ten seconds from one client and subscribing five in ten minutes, and nothing else was counted.
