## 0.3.0

2026-11-24. [Release page](https://github.com/Taqanah/raaqeb/releases/tag/v0.3.0)

0.3.0 is the security release for 0.2.x, and it makes Raaqeb a tool for a team: roles, single sign-on, an audit log, a management API, private status pages and remote probes. **Upgrade every 0.2.x install: no 0.2.x release will follow.** Read "Before you upgrade" first, because there is no way back to 0.2.x.

<Callout type="warn">
**Two vulnerabilities rated high are fixed.** Raaqeb 0.2.x runs on Bun 1.4.3. A site you monitor, or one a check is redirected to, could send a crafted brotli answer that writes past a buffer in Raaqeb's memory (CVE-2026-111497). Someone in the network path could impersonate any server Raaqeb connects to, with certificates from eMudhra's emSign authority, whose keys were compromised and published: monitored sites, webhooks and other channels, your mail server and your sign-in provider. 0.3.0 runs on Bun 1.4.5, which fixes both.
</Callout>

### The short version

- **Security fixes** in the runtime, for every 0.2.x install
- **Teams**: five roles, invitations and a team page
- **Single sign-on** through an OpenID Connect provider
- **An audit log** of every change and every sign-in
- **A management API** with API keys
- **Private status pages**
- **Remote probes** that confirm an outage from a second location
- **Uptime reports**, **recurring maintenance** and **domain registration warnings**
- **PagerDuty, Microsoft Teams and Google Chat** channels, a **MongoDB** monitor and a **Prometheus** endpoint
- **Rate rules** on sign-in, password resets and subscriptions

### Before you upgrade

**Every install**
- **Back up first: there is no way back to 0.2.x.** 0.3.0 migrates the database forward, and 0.2.x then refuses to open it. On SQLite, Raaqeb first copies the database into `snapshots/`. On Postgres it copies nothing, so take a `pg_dump` yourself. That copy is the only way back.
- **Behind a reverse proxy, set Trusted proxies.** Set them in the general settings or with `RAAQEB_TRUSTED_PROXIES`. Without them every visitor reaches Raaqeb as the proxy, and all of them share one count under the new rate rules.
- **Search each status page's custom CSS for `http://`.** Every page now sends a content security policy, so custom CSS may load fonts, images and stylesheets over `https:` or `data:` only. Whatever it loads over `http:` stops applying, and nothing warns you. Change it to `https://` before you upgrade.
- **Exports are a new version.** 0.2.x cannot import a file 0.3.0 writes. It carries the accounts (without passwords) and the audit log, which records addresses, so store it as you store a backup. Exports from 0.1 and 0.2 still import.
- **Your account becomes the owner.** If its name is still the default `operator`, the name is cleared for you to set.

**Monitors**
- **Three eMudhra roots are no longer trusted.** They are emSign Root CA - C1, emSign ECC Root CA - C3 and emSign ECC Root CA - G3, and a chain through the compromised emSign keys is refused. A site whose certificate chains only to one of them reads as an invalid certificate.
- **Three certificate verdicts change.** An expired certificate from an issuer Raaqeb does not trust reads as expired, where it read as invalid. A root in a monitor's **Trusted CA certificates** whose extended key usage leaves out server authentication, or a root with a path length of 0 that signs through an intermediate certificate, now reads as an invalid certificate. If a monitor that trusts its own root reads down after the upgrade, look at that root first.
- **Request headers stop at another origin.** No entry of a monitor's **Request headers** follows a redirect to another host, port or protocol, `http` to `https` included. A monitor that needs a header at the final address reads down until you point it there.
- **Some database addresses are refused.** A Postgres or MySQL monitor whose address names a socket, a file or another host is refused: a `%` in the host, or `path`, `socket`, `host`, `port`, `sslrootcert`, `sslcert` or `sslkey` in its query. One already saved reads down until you edit it. `sslrootcert=system` is allowed.
- **Postgres arrays read as JSON.** A Postgres monitor reads 35 more array types as JSON: a `uuid[]`, range or `tsvector[]` column answers `["…"]` where it answered `{…}`. Rewrite an expected value written the old way; **Test now** shows the new answer.
- **Domain registration warnings are on.** They are turned on for every existing HTTP, TCP and DNS monitor that sends notifications and whose host is a domain name. Once a day Raaqeb asks IANA's data site, then the registry's RDAP server or its WHOIS server on port 43, about the registered domain only. Allow them in your firewall, or turn the warning off on the monitor.
- **A heartbeat can now report failure.** A call to `/fail`, or with `status=fail`, `status=down` or a non-zero `exit=`, takes its monitor down, where every call meant the job ran. Check cron scripts that pass a changing status.
- **HTTP checks send `User-Agent: raaqeb/0.3.0`** where they sent `raaqeb/0.2.2`. Write a rule for `raaqeb/`.

**Sign-in and limits**
- **Rate rules replace 0.2.2's limit** of 64 open requests from people who are not signed in, 16 per client. Past a rule the answer is `429` with `Retry-After`, and the form asks to wait. Sign-in takes six tries at once from one network, then one every 10 seconds, and one account takes ten wrong passwords in 15 minutes from browsers that have not signed in to it. A request body that has not arrived whole in 2 seconds is answered `408`.
- **Signed-in accounts have limits too.** An account can send the sign-in email test or change its email five times, then once every 2 minutes, and change its password or second step six times, then once every 10 seconds. An owner who presses the test six times in a row meets this.
- **A new cookie, `raaqeb.known`.** A browser that signs in gets it, and it keeps that browser's own allowance under the rules. It grants no access. If you filter cookies, allow it.
- **Sign-in mail goes only through the email channel an owner chose.** An upgrade records the oldest email channel as the choice. When the chosen channel is deleted, reset links, one-time codes, invitations and subscriber email stop until an owner chooses another, where 0.2.x fell back to the oldest email channel.

**Integrations and the command line**
- **Webhook receivers get new values.** One that checks against a fixed list must accept the new events `monitor.domain_expiring`, `probe.silent` and `probe.reporting`, the new reasons `heartbeat_failed`, `proxy_failed`, `client_certificate_expired`, `client_certificate_refused`, `oauth2_token_failed` and `tls_proxy_unsupported`, and the optional `failure` and `locations` on a down notice.
- **Remove `--preload` from `BUN_OPTIONS`.** Raaqeb refuses to start while it is there.
- **`raaqeb reset-password` and `raaqeb set-address` need an install.** In a folder that holds none they exit with a message, where they left a new install key behind. On Postgres they need the install key, as `serve` does.

### New features

**Teams and access**
- **Roles and invitations.** Five roles (owner, admin, editor, responder and viewer), invitations that last seven days and a team page. Lowering a role signs that person out at once.
- **Single sign-on.** Sign in through one OpenID Connect provider, such as Keycloak, Authentik, Okta, Entra ID or Google Workspace. Choose who may sign up and a role for each claim, and leave passwords to owners alone if you like.
- **Audit log.** Every change behind a permission, every sign-in and every refused one, filtered by account, kind and dates, and kept at least 90 days.
- **Management API.** Monitors, groups, status pages, components, incidents, maintenance, channels and probes under `/api/v1/`. API keys belong to one account and can take a lower role and an expiry.
- **Private status pages.** Behind a page password, behind sign-in to the install, or for allowed addresses only. A private page is never indexed or cached publicly.

**Monitoring**
- **Remote probes.** `raaqeb probe` on another server checks the monitors you give it, so an outage can be confirmed from a second location before it opens. A silent probe reads unknown, never down.
- **Uptime reports.** For a monitor, group, component or status page over a month, a quarter or chosen days: uptime against a target, the error budget, downtime, outages and recovery time, as a page, a CSV file or a print.
- **Recurring maintenance.** Weekly or monthly windows at a time on a chosen time zone's clock. The status page shows the next one.
- **Domain registration warnings.** A warning 30 days before a monitored domain's registration ends.
- **Heartbeat failure reports.** A job can report that it failed, with an exit code and a message that reach the down notice. The monitor's page lists its last ten heartbeats.
- **HTTP monitor authentication.** Present a client certificate, trust your own certificate authority, and get a bearer token by OAuth 2.0 client credentials.
- **Outbound proxy.** The install's `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` and `NO_PROXY` route HTTP checks, channels, subscriber webhooks and the release check, and an HTTP monitor can name its own proxy. A refusing proxy reads as the proxy's failure.
- **MongoDB monitor.**

**Notifications and integrations**
- **PagerDuty, Microsoft Teams and Google Chat** channels.
- **Prometheus metrics** at `/metrics`, off until you turn it on in Settings, Metrics.
- **A hold after an import.** Importing a backup holds every notification until an owner or admin presses **Resume notifications**. Untick **Hold notifications** when you restore your own install.

### Fixes

**Security**
- A monitor's custom headers, such as `X-Api-Key`, followed a redirect to another origin.
- A proxy sign-in written into `HTTP_PROXY` could appear in what a check stores, which every operator can read. It is hidden as a monitor's own proxy sign-in is.
- A few addresses that held forms open could keep everyone else from signing in or subscribing for as long as they kept at it.
- Guessing a password from many networks had no ceiling. Now it is ten wrong tries per account in 15 minutes, and five password checks a second for the whole install, from browsers not known to it.
- A signed-in account could send sign-in test emails and run password checks without limit.

**Reliability**
- On Postgres, the monitor list or a status page with many components could run the install out of memory just after it started, and at 00:15 UTC each night.
- An export of an install whose status pages hold more than about 6 MB of images could not be imported. Every export now imports.
- A Postgres monitor's query that outlived its timeout ran on to its end on the monitored server, every interval. It is now stopped there, and Raaqeb's own Postgres statements that outlive the answer limit give their connection back.

**Messages and pages**
- Onboarding's connection test showed an untrusted Postgres certificate as an unexpected error. It names a TLS failure.
- The reason for a MySQL 8 sign-in that needs an encrypted connection was not true while the server's password cache was warm. It now says the server asked for an encrypted connection to check the password.
- A not-found under a status page's own language address read in the install's language when the two differed.
- `/favicon.ico` and `/robots.txt` answered the not-found page.

### Changes

- Raaqeb runs on Bun 1.4.5. Each binary is about 19 MB larger, and the installers download it compressed: 42 MB as `.zst` for Linux x64, or 53 MB as `.gz`. The raw binaries stay in each release for older installers and mirrors.
- The monitor list shows a row's first tag and how many more beside the open sidebar, and the sidebar fits a screen 720 px tall.

**Full changelog**: [v0.2.0...v0.3.0](https://github.com/Taqanah/raaqeb/compare/v0.2.0...v0.3.0)

## 0.2.2

2026-11-23. [Release page](https://github.com/Taqanah/raaqeb/releases/tag/v0.2.2)

Fixes for 0.2.1, chiefly to memory: with 200 monitors late in the UTC day, opening the monitor list or a status page with many components no longer runs the install out of memory. Raaqeb still belongs behind a reverse proxy: reached directly from the internet, an install can still be run out of memory by clients that open many connections and never read the answer.

### Before you upgrade

- A request from someone who is not signed in may carry a body of at most 64 KiB; a larger one is answered `413` before Raaqeb reads it. The forms visitors send are a few kilobytes, and a signed-in operator's requests, heartbeats and imports keep their limits. Behind a reverse proxy, some of these answers can reach the client as `502`.
- When many requests that carry a body arrive at once from people who are not signed in, such as sign-ins, subscriptions and any other form they send, those past 64 open at once, or past 16 from one client, are answered `503` with `Retry-After: 1`. Heartbeats and a signed-in operator are never held back. A few IP addresses that hold such requests open can keep people who are not signed in from signing in or subscribing for as long as they keep at it; the install stays up meanwhile.
- Behind a reverse proxy, set **Trusted proxies** in the general settings, or `RAAQEB_TRUSTED_PROXIES`: without them every visitor reaches Raaqeb as the proxy, and all of them share one client's 16.
- HTTP checks send `User-Agent: raaqeb/0.2.2` where they sent `raaqeb/0.2.1`. A rule on a monitored site or a firewall written for the whole value no longer matches: write it for the name before the slash, `raaqeb/`, so the next release matches too.
- A status page address written with percent-escapes (`%61` for `a`), or ending in a second slash, answers `404` where it showed the page. Raaqeb's own links never take that form.

### Fixes

- With 200 monitors late in the UTC day, the first load of the monitor list, or of a status page with 200 components, ran an install out of memory at 240 MB. Each now loads in about a second within it, and on a smaller install they load a little faster and use less memory.
- A few large requests, or many slow ones, from people who are not signed in no longer run an install out of memory.
- A flood of a status page's addresses, real ones or one address spelled many ways, no longer makes its overview answer `503` or wait a minute: the overview stays in memory and is refreshed ahead of the page's other addresses.
- A heartbeat posted with a body that has no length, such as `curl -X POST -T -` or a fetch of a stream, is recorded, where it got `413` and its monitor read down.
- Restoring a backup larger than the install's memory no longer runs it out of memory.
- Exporting an install whose status pages hold many images no longer runs it out of memory, and the file is the same as before. A limit stays: when the images of all status pages come to more than about 6 MB, the export is written but no version of Raaqeb can import it yet, so keep a copy of the data directory too.
- The request log hides a heartbeat's or a password reset's token however its address is escaped; some escaped forms showed it in full.
- A sign-in, password reset or onboarding form sent before the page has finished loading keeps what was typed: its button waits until the page is ready, where the form came back empty.
- In Arabic, the refusal of an import over the limit shows its size with the number before the unit, where the unit came first, and a list of names separates every name with the Arabic comma, a Latin name included, where an Arabic "and" was glued onto a Latin name.

### Changes

- English lists of names, such as the components an incident affects, read "A, B" where they read "A and B": on the status page, in the feed and in the admin.
- A server function call that fails writes one log line, `raaqeb: a server function failed: <reason>`, where it wrote a stack trace with the install's file paths.

## 0.2.1

2026-11-22. [Release page](https://github.com/Taqanah/raaqeb/releases/tag/v0.2.1)

Fixes for 0.2.0, chiefly to memory: a flood of requests from people who are not signed in, or of sign-ins, no longer runs an install out of memory.

### Before you upgrade

- Raaqeb sets its data directory to mode 0700 at every start when the folder is its own to change, where 0.2.0 only noted in the log that the mode was wider. A backup tool or another user that read the folder through its group or other permissions loses access: run it as the user Raaqeb runs as, or as root.
- When many requests arrive at once, someone who is not signed in can get `503` with `Retry-After: 1` for a page Raaqeb has to build. A signed-in operator is never held back. A tool that loads many pages at once, such as a link checker or a monitor of a status page from outside, may count these as failures.
- HTTP checks send `User-Agent: raaqeb/0.2.1` where they sent `Bun/1.4.3`. A site or firewall that treats requests by this header may answer differently: one that refused Bun's lets checks through, and a rule written for the old value no longer matches. A `User-Agent` entry in **Request headers** replaces it.

### Fixes

- An address that does not exist answers a small `404` page of about 1 KB, where 0.2.0 built the whole app, 209 KB, for each one: a tool trying made-up addresses could run an install out of memory.
- The other pages someone who is not signed in can open, such as sign-in, a password reset, onboarding and a subscription's page, are served from memory or built one at a time, so a flood of them no longer grows memory.
- Sign-ins that arrive together have their passwords checked one after another, so a burst of them no longer runs an install out of memory.
- A second `raaqeb serve` started while another holds the port exits before it opens the database, so an upgrade started beside a running install no longer migrates that install's database.
- A not-found under `/en/` or `/ar/` reads in that language.
- An address that does not exist under Settings shows one notice under the Settings title, where the title appeared twice.
- The copy button of a status page's "Get updates" dialog, with Feed chosen, reads "Copy" where it showed `app_copy`.
- The confirmation after "Forgot password?" no longer shows whoever sends the form the `raaqeb reset-password` command; it links the docs on resetting a password.
- In a content field, the install language's input is marked "Required", and screen readers announce it as required.

### Changes

- An API address, such as `/health`, a feed or a badge, answers a method it does not take with `405` and an `Allow` header, and an address that does not exist under `/api/` answers a plain-text `404`. Both answered with the app's page.

## 0.2.0

2026-10-14. [Release page](https://github.com/Taqanah/raaqeb/releases/tag/v0.2.0)

A request log, `--version` and `--help`, stricter imports and subscriber webhooks, and polish on every screen.

### New features

- A request log: turn it on in Settings, General, and the server log gets one line per request with its status code, duration, visitor address and browser. It takes effect without a restart.
- `raaqeb --version` prints the version, and `raaqeb --help` lists the commands.
- On a monitor's page, the checks list loads more with "Show more", and follows the chart when you zoom it.
- Deleting a component names the incidents and maintenance windows deleted with it.
- Changing the account email asks for the current password, and the old address receives a notice naming the new one.
- An email channel's failed send says whether the SMTP server never greeted or stopped answering during the send.
- Signing out explains when the browser's address is not the public address, with the command that fixes it, and the general settings warn before you save an address that would cause it.
- The admin, and a status page with no favicon of its own, show Raaqeb's icon.
- A page's brand colour fills the status page's buttons.

### Fixes

- A notification channel saved twice without a reload keeps its fields: the second save no longer resets ntfy's server or drops the email and Telegram fields.
- A form sent twice before it answers saves once.
- "Send a test message" in the sign-in settings sends through the email channel selected in the form.
- The first page after signing in or out is in the right language.
- On Postgres, `/health` and the pages answer within about 4 seconds when the database stops answering.
- A failed SMTP attempt closes its connection.
- A fresh Docker install no longer warns about the data folder's permissions.
- A maintenance window's page follows its stage without a reload.
- Keyboard focus is visible on every control and is never lost.
- A name written in the other language is cut at its end, so its start stays in view.
- The monitor list fits beside the open sidebar at every width.
- An import checks page images as an upload does, and refuses a line too large to read and any monitor or channel its form would refuse.
- The subscriber webhook filter blocks every internal address range, and posts to the address it checked.
- Log lines hide tokens in every path and drop control characters.
- The new release banner links to release notes over https only.
- Polish on the monitor, sign-in, account, channel, settings, status page, incident and maintenance screens.

### Changes

- Password reset requests are limited to three a minute from one address.
- A database monitor's query reads at most one row.
- The status page's theme switch shows a sun, a moon and a screen instead of words.

## 0.1.0

2026-10-10. [Release page](https://github.com/Taqanah/raaqeb/releases/tag/v0.1.0)

The first stable release: what the docs describe, installed by the installer or the Docker image.

## What a release carries

A release's download folder, `https://github.com/Taqanah/raaqeb/releases/download/<tag>/`, is where the installer downloads from, and the address it takes in `RAAQEB_DOWNLOAD_URL` if you mirror it. It holds:

- One binary per platform, and each compressed as `.zst` and `.gz`, which the installers download.
- `SHA256SUMS`, listing every file: the installer checks the compressed file against it before unpacking it, and the binary after.
- The two installers, `install.sh` and `install.ps1`.

The Docker image is `ghcr.io/taqanah/raaqeb`, tagged with the version, such as `ghcr.io/taqanah/raaqeb:0.1.0`.

The installer's address, `https://raaqeb.dev/install.sh`, serves the script of the latest stable release. A release whose tag carries a suffix, such as `v0.3.0-beta.1`, is a pre-release: it is never the latest, and you install it with `RAAQEB_VERSION=0.3.0-beta.1`.

## Learning of a newer release

The admin area shows a banner when a newer release exists. Raaqeb never updates itself; how to upgrade each kind of install is in [Upgrades](/en/docs/operate/upgrades).
