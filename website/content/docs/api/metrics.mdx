يستطيع راقب أن يعرض حالة كل مراقبة على العنوان `/metrics` بصيغة Prometheus النصية، ليقرأها Prometheus أو Grafana Agent أو أي أداة أخرى تجمع المقاييس. وهو مطفأ حتى تفعّله. تقرأ كل قراءة آخر فحص لكل مراقبة وسجل شهادتها وآخر سبعة أيام لها ولا تُنتج صفحة، فتكلّف قليلًا: مع 200 مراقبة وفحوص يوم كامل كل دقيقة تستغرق نحو 150 ملّي ثانية وأقل من 50 ميغابايت إضافية، لأن فحوص اليوم تُجمع داخل قاعدة البيانات ولا تُحمَّل واحدًا واحدًا. والمراقبة التي لا فحص لها اليوم، مُعلَّقة أو لم تُفحص بعد منتصف الليل، تكلّف أكثر، لأن راقب يفتح آخر يوم مختوم لها ليجد آخر فحص: 200 منها استغرقت نحو 20 ملّي ثانية و30 ميغابايت في القراءة الواحدة.

## التفعيل

افتح **الإعدادات** ثم **المقاييس**، واختر **تفعيل المقاييس**. ينشئ راقب رمزًا ويعرضه مرة واحدة، ومعه إعداد Prometheus الذي يستعمله. انسخ الرمز حينها: لا يحفظ راقب إلا بصمة SHA-256 له، فلا يستطيع عرضه ثانية. و**رمز جديد** ينشئ رمزًا آخر ويوقف الرمز الحالي فورًا. و**تعطيل المقاييس** يحذف الرمز، فيعود `/metrics` يجيب بالرمز `404`. ولا ينتقل الرمز في [التصدير](/docs/operate/export-import).

يرسل Prometheus الرمز بوصفه رمز Bearer:

```yaml
scrape_configs:
  - job_name: raaqeb
    scheme: https
    authorization:
      credentials_file: /etc/prometheus/raaqeb-token
    static_configs:
      - targets: ["status.example.com"]
```

يحمل `credentials_file` الرمز وحده في سطر واحد، أما `credentials` فيضعه في الإعداد نفسه كما تعرضه صفحة الإعدادات. والطلب الذي لا رمز فيه أو رمزه خاطئ يُجاب بالرمز `401` ولا شيء بعده، فيسهل أن ترى في صفحة أهداف Prometheus أداةً لا تستطيع الدخول.

## المقاييس

كل مقياس من نوع gauge، وتوسمه أربعة وسوم: `monitor` اسم المراقبة وقد يتشارك اسمٌ واحد مراقبتان، و`monitor_id` معرّفها وهو لا يتكرر ويفرّق بين مراقبتين باسم واحد، و`group` مجموعتها وهو فارغ إن لم تكن لها مجموعة، و`check_type` نوع الفحص (`http` أو `tcp` أو `dns` أو `postgres` أو `mysql` أو `redis` أو `mongodb` أو `docker` أو `heartbeat`).

| المقياس | القيمة |
|---|---|
| `raaqeb_monitor_up` | `1` إذا كانت نتيجة آخر فحص «يعمل» أو «متعثّر»، و`0` إذا كانت «متعطّل». لا يظهر والمراقبة مُعلَّقة ولا قبل أول فحص لها. |
| `raaqeb_monitor_degraded` | `1` إذا نجح آخر فحص لكنه تجاوز حد التعثّر في المراقبة، وإلا `0`. ويغيب حيث يغيب `raaqeb_monitor_up`. |
| `raaqeb_monitor_paused` | `1` ما دامت المراقبة مُعلَّقة، وإلا `0`. |
| `raaqeb_monitor_response_seconds` | زمن استجابة آخر فحص بالثواني. لا يظهر والمراقبة مُعلَّقة، ولا لفحص بلا زمن استجابة. |
| `raaqeb_monitor_last_check_timestamp_seconds` | وقت بدء آخر فحص بالثواني منذ بداية عصر Unix. |
| `raaqeb_monitor_uptime_ratio` | حصة الوقت المرصود للمراقبة خلال آخر سبعة أيام بتوقيت UTC، ومنها اليوم، التي لم تكن فيها متعطّلة، من 0 إلى 1، وتحمل الوسم `window="7d"`. تستثني نوافذ الصيانة والفجوات التي لا فحوص فيها، كما في صفحة الحالة. لا تظهر ما دام لا وقت مرصود للمراقبة. وتحتفظ المراقبة المُعلَّقة بالنسبة التي حصّلتها. |
| `raaqeb_certificate_expiry_timestamp_seconds` | وقت انتهاء شهادة TLS للمراقبة بالثواني منذ بداية عصر Unix. يظهر لمراقبة HTTPS خيار انتهاء الشهادة فيها مفعّل، بعد أن يقرأ راقب الشهادة. |
| `raaqeb_build_info` | قيمته `1` دائمًا، ويحمل الوسم `version` بإصدار راقب الجاري. |

لا يظهر `raaqeb_monitor_up` للمراقبة المُعلَّقة، لأن آخر فحص لها سابق لتعليقها؛ ووقتها بلا بيانات كما في صفحة الحالة.

## التنبيهات ونسبة التوفّر

المقاييس هي آخر فحص لا سجل الفحوص، فيحتفظ Prometheus بالسجل. لتنبيه عند تعطّل مراقبة:

```yaml
- alert: MonitorDown
  expr: raaqeb_monitor_up == 0
  for: 2m
```

ولشهادة تنتهي خلال 14 يومًا: `raaqeb_certificate_expiry_timestamp_seconds - time() < 14 * 86400`. ولنسبة توفّر خلال أسبوع استعمل `raaqeb_monitor_uptime_ratio`، وهي نسبة راقب نفسه وتستثني نوافذ الصيانة والفجوات من الحساب، أو `avg_over_time(raaqeb_monitor_up[7d])`، وهي تعدّ وقت الصيانة تعطّلًا وتقبل أي مدة تختارها.

لا تقرأ بأسرع مما تفحص المراقبات: لا تتغير قيمة المراقبة إلا حين يجري فحصها، كل دقيقة افتراضيًا. و`raaqeb_monitor_last_check_timestamp_seconds` يخبرك إن كانت القيمة حديثة.
